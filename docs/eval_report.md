# 평가 리포트 (6회차 선택 과제)

> 전제. 이 폴더의 `results/agentic.json` · `judge.json` · `judge_calibration.json` · `calc_e2e.json` 은
> 모두 **가짜 모델**로 만들어졌다(OpenAI 키가 401 로 거부됨). 가짜 모델은 필터를 뽑지 않고, 판정은 항상
> "sufficient", 답변은 고정 문구, 계산 파라미터 추출은 비어 있다. 그래서 아래 세 줄은 "LLM 이 빠지면
> 파이프라인이 어디서 무너지는가"를 읽는 리포트가 된다. 키가 살아나면 같은 명령으로 다시 쓴다.

## 1. 3단계 비교 (`make compare`, Recall@5 · MRR 유형별)

- **계산형이 가장 많이 올랐다.** MRR 30.0% (baseline) → 80.0% (hybrid) → 80.0% (agentic). 금액·비율이 많은 질문은 Dense 가 숫자를 뭉개는데 Kiwi BM25 가 "연체이자율" 같은 사전 낱말과 숫자 원형을 잡아 준다. agentic 은 hybrid 를 그대로 쓰므로 유지됐다.
- **조항번호형이 agentic 에서 가장 많이 내려갔다.** Recall@5 100% → 87.5% → 50.0%, MRR 75.0% → 83.3% → 40.0%. hybrid 까지는 좋았는데 agentic 에서 꺾인 이유는 가짜 모델의 rewrite 노드가 질문을 `{}` 로 고쳐 쓰고 selfquery 가 필터를 비워, 검색어가 원문 그대로 못 들어갔기 때문이다. 검색기가 나빠진 게 아니라 **그 앞의 LLM 단계가 비어서** 생긴 하락이다. 실제 키로 다시 돌리면 이 행이 agentic 의 진짜 값이 된다.
- **메타데이터형·복합형도 같은 이유로 내려갔다.** 메타데이터형 MRR 50.0% → 45.0% → 10.0%, 복합형 57.3% → 90.0% → 22.9%. 둘 다 "2013년판", "분쟁조정사례" 같은 조건을 Self-Query 가 필터로 뽑아야 사는 유형이다. `results/filter_accuracy.json` 에서 S15 · S19 · S26 · S28 · S29 · S35 · S38 의 기대 필터가 전부 `None` 으로 뽑힌 것이 그 증거다. 유사상품비교형만 66.7% → 100%(Recall@5)로 올랐는데, 이는 agentic 이 후보를 더 많이 읽는(top_k 8) 효과다.

## 2. judge 와 사람이 가장 어긋난 문항 (`results/judge_calibration.json`)

- **S25, judge 2/6 vs 사람 6/6, 차이 −4.** 어긋난 항목은 `numeric_ok` 와 `no_extra_claim` 둘(각 0 vs 2). 가짜 judge 는 근거 일치만 기계로 매기고 나머지 둘을 0 으로 두기 때문에 **박하게** 나왔다. 17문항 전체로도 basis_match 는 완전 일치 94% 인데 numeric_ok 24%, no_extra_claim 6% 라 치우침이 그 두 항목에 몰려 있고, judge − 사람 평균이 −3.23 으로 방향이 일정하다. 실제 judge 로 다시 재면 이 두 항목의 MAE 가 얼마로 줄어드는지가 캘리브레이션의 핵심 숫자다. 참고로 basis_match 의 기계 채점(인용 청크 ∩ gold)이 사람과 94% 맞는다는 것은, 근거 일치 항목은 LLM 없이도 거의 잴 수 있다는 뜻이다.

## 3. 계산 틀린 문항 (`results/calc_e2e.json`)

- **C06 loan_prepayment_fee, 기대 466,666원, 결과 "계산 안 함".** 함수가 틀린 게 아니라 **추출이 없었다.** `tests/test_calc_golden.py` 32개가 통과하므로 같은 함수에 (1억 원, 1.4%, 잔여일/전체일) 을 넣으면 466,666 이 나온다. 가짜 모델은 extract 노드에서 `{}` 를 돌려 파라미터가 비고, 에이전트는 "파라미터 없음 → 계산 안 함"으로 안전하게 멈췄다. 15문항 중 13개가 같은 모양이고, 맞은 2개(C10 범위형, C15 미답변형)는 "계산하지 않는 것"이 정답인 문항이다. 즉 지금 결과는 계산 함수의 정확도가 아니라 **"추출이 비면 숫자를 지어내지 않는다"는 안전장치**가 작동함을 보여 준다. 실제 키로 돌린 뒤 틀리는 문항이 있으면 그때 `how` 열로 함수 오류인지 추출 오류인지 가른다.
